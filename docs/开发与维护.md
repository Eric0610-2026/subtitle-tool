# 开发与维护

本指南面向维护者。用户安装与操作见 [README](../README.md) 和 [使用说明书](使用说明书.md)；模块职责、事件契约和架构约束见 [AGENTS.md](../AGENTS.md)。以下命令在项目根目录的 Windows PowerShell 中执行。

## 修改前

1. 阅读 AGENTS.md，执行 `git status --short`，确认并保留已有改动。
2. 添加新功能前向用户确认；需求不明确时先确认范围。修正文档时以当前实现、配置模板和测试为依据。
3. 精准查找相关模块，避免为了解一个行为通读所有大文件。核心模块、数据流或配置结构变更后同步维护 AGENTS.md 与 README。

## 环境与运行

建议创建独立环境，并在后续命令中使用同一解释器：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tools/requirements.txt
.\.venv\Scripts\python.exe subtitle_app/subtitle_app.py
```

实际运行需要按 README 准备 ffmpeg/ffprobe、Whisper 模型和按需使用的 llama.cpp、Hy-MT2 模型。单元测试通过模拟调用运行，无需下载或加载模型。

入口会检查依赖指纹；首次启动、依赖清单或解释器变化时可能联网安装依赖。转写和翻译本身在本机运行。GPU 环境按所安装组件的官方兼容说明配置，不把某一旧 CUDA 安装命令当成通用要求。

## 配置与文件归属

| 路径 | 维护规则 |
| --- | --- |
| `subtitle_app/config.example.json` | 提交到仓库的默认配置模板；改变默认值应修改此处 |
| `subtitle_app/config.json` | 本机设置，不提交；缺失时读取模板，已有配置缺少的字段由模板补齐 |
| `models/`、`tools/llama-cpp/` | 本地模型与推理程序，不随源码分发 |
| `cache/` | 翻译缓存、已完成记录、依赖标记和本地服务日志；不能当作无差别可删的临时目录 |
| `logs/` | 应用日志与 `srt_backup/` 字幕备份；排障或迁移前保留所需内容 |
| 输入媒体所在目录 | 输出字幕、视频及断点文件；测试不得使用真实用户媒体 |

「本次有效」影响当前会话随后启动的任务；「永久保存（下次默认）」还写入本机配置。正在运行的任务使用启动时冻结的快照。手工修改配置后重启应用；重置前可先备份自己的配置文件。

## 验证

字幕预览上限由 `srt_utils.PREVIEW_BLOCK_LIMIT = 100` 定义，发送端与界面共用。`transcriber.py` 只发送连续的前 100 段实时预览，断点恢复时先补入已有字幕的开头；后续处理与进度事件照常执行。`PreviewPanel` 填满后保存前 100 行的显示快照，不再为后续追加启动定时器，也不重绘后台完成/翻译事件带来的全文。全文保存在 `_raw_text`，保存、时间偏移和分页编辑均使用全文。若终版与冻结的预览内容不同，表格保持只读，避免把旧显示内容写到新的字幕位置；用户主动打开文件或提交编辑时重新预览前 100 行。主题切换使用冻结快照更新配色；新文件的 `preview_clear` 解除冻结。回归检查覆盖 5000 段字幕、冻结后零渲染、全文保留、编辑映射、续转和进度更新。

本地模型管理入口位于 `qt_app.py`，界面由 `dialogs.ModelManagerDialog` 实现。主页仅保留管理入口；实际已加载模型名称与状态合入各模型区域，Whisper 名称由 `Transcriber.loaded_model_name()` 在缓存锁内读取，避免设置目录变化导致名称失真。打开弹窗时重新检查状态；运行中的加载事件及主任务结束会刷新可见弹窗，定期服务探测仍在后台执行。Whisper 手动加载复用 `worker.transcriber` 缓存，目录必须含本地 `model.bin`；Hy-MT2 加载复用 `local_service.ensure_running()`，手动卸下、转写前清理和彻底退出统一调用 `shutdown_service()`，返回 `(ok, detail)`。它先关闭本会话进程，再通过 `windows_service.py` 核实外部服务：监听固定端点、程序路径与项目 `llama-server.exe` 一致、模型参数为项目 `models/hy-mt2` 下的绝对 `.gguf` 路径。Windows 进程句柄保持打开，创建时间与 CIM 信息核对一致，终止前复查监听 PID，同一句柄结束并等待退出；端口被新进程接管时不追杀。服务尚未就绪但仍监听时显示待核实状态，保留卸下入口。识别、权限或关闭失败返回具体原因，不把仍运行的服务显示为已卸下。`shutdown_owned()` 继续用于启动失败及取消时只清理本次拉起的进程。管理操作与主任务互斥，状态检查由后台线程执行，使用操作代次忽略过期结果。模型加载期间彻底退出时取消服务等待；不可中断的 Whisper 构造结束后释放缓存。`tools/tests/test_model_manager.py` 覆盖操作、失败、互斥、状态和浅深色 Qt 渲染，`tools/tests/test_windows_service.py` 覆盖模拟终止及只读原生进程信息检查，测试清理入口必须模拟，不能终止用户服务；真实推理应另外验收。

按钮鼠标指针由 `widgets.install_button_cursors()` 在应用启动时统一设置，覆盖 `QAbstractButton` 派生控件（普通按钮、图标按钮、复选框和 Qt 提示框按钮）。可用按钮在悬停及按下时显示手形，禁用时显示箭头；动态创建和重新启用的按钮自动更新，无需在每个页面重复设置。Windows 原生文件选择器由系统管理。

修改完成后必须运行全量测试，即使本次只修改文档：

```powershell
python -m unittest discover -s tools/tests
python -m unittest tools.tests.test_translator
python -m unittest tools.tests.test_translator.TestBatchSizePersistenceField
git diff --check
```

使用虚拟环境时，将上面的 `python` 换成 `.\.venv\Scripts\python.exe`。测试数量以当前运行结果为准，历史审查记录的数量不随新增用例改写。

- 模型加载、`ensure_running`、网络请求和媒体子进程必须模拟，防止测试启动真实服务。
- 翻译编排测试将 `translator._BACKUP_DIR` 指向临时目录；缓存、配置、断点及媒体输出也应隔离。
- 测试前后核对是否新增 `llama-server.exe` 进程；若有，先确认归属，不能终止用户已有服务。
- 单元测试通过只证明其覆盖的行为；真实 GPU 推理、媒体内嵌及视觉效果应分别报告是否验证。
- 界面颜色、主题切换或布局变更，应检查实际渲染效果；性能结论注明样本、环境和测量范围。

可疑翻译配置与密钥扫描：

```powershell
git grep -nE 'api_key|api_url|preset|sk-[A-Za-z0-9_-]{20,}' -- subtitle_app tools
```

命中后逐项检查，不机械要求零命中：ffmpeg 的 `preset` 编码参数与测试中的禁止字段断言可能合法。不得新增外部翻译端点、密钥设置或厂商适配分支；本地翻译端点由 `local_service.translation_endpoint()` 单点提供。分享扫描结果前确认没有真实密钥。

## 排障入口

| 现象 | 优先检查 |
| --- | --- |
| 启动失败 | 终端错误、Python 解释器与依赖、配置 JSON 格式 |
| 转写失败 | 模型路径、ffmpeg/ffprobe、设备与精度、`logs/subtitle_tool.log` |
| 翻译服务未启动 | `tools/llama-cpp/` 程序与 DLL、`models/hy-mt2/` GGUF、`cache/.llama-server.log` |
| 服务就绪但翻译无进展 | 实际生成日志、截断或重复响应、拆批与停止行为；健康检查成功不等于生成成功 |
| 窗口关闭后任务还在运行 | 正常托盘行为；从托盘恢复，选择「彻底退出」才能退出 |
| 内嵌失败 | ffmpeg 退出状态、输出时长验证及输入字幕；保留原媒体后再排查 |
